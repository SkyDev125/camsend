# Simulator and benchmark findings

The benchmark must report decoded file bytes only after exact reconstruction and SHA-256 verification. It separates raw optical symbol rate, recovered encoded payload, verified original-file goodput, and compression-adjusted throughput. This follows the measurement literature's emphasis on calibrated geometry and unstable optical factors. [systematic measurement](https://arxiv.org/abs/1501.02528), [capacity under perspective](https://www.sciencedirect.com/science/article/abs/S1574119214001849)

The reproducible pipeline is: render a frame, apply seeded geometry/blur/exposure/colour/noise/rolling-shutter/obstruction effects, optionally drop or duplicate the frame, decode with the same reference decoder, then run fountain recovery and SHA-256 verification. Each run emits a JSON report with seed, mode, grid, frame count, unique/duplicate/rejected frames, correction counts, decode timings, confidence, and throughput.

Retention gates compare candidate modes on the same fixture matrix. A change is retained only if it improves verified goodput without a statistically meaningful reliability regression, or materially reduces decoder cost/compatibility risk. Real-camera exports use the same schema and never include payload bytes unless an explicit recording option is enabled.
The benchmark's primary elapsed time is deterministic simulated display time (`frame count / nominal frame rate`); decoder CPU time is reported separately. This prevents machine speed from changing the headline transfer comparison while still exposing decode cost. Reports distinguish `rawOpticalBitrateBitsPerSecond`, `nominalEncodedPayloadBitrateBitsPerSecond`, `recoveredPayloadBytesPerSecond`, `recoveredPayloadBitrateBitsPerSecond`, and verified original-file goodput in both bytes/s and bits/s.

## Impairment hardening matrix

Run `npm run benchmark:matrix` to exercise all retained profiles against the same seeded fixture set: clean, mild geometry/exposure, blur/defocus, glare/shadow/quantization, rolling shutter, and partial obstruction. The command uses a bounded 3 KB/8-frame smoke matrix; callers that need full-size or physical-fixture-scale runs can use the exported `runImpairmentMatrix` function with explicit limits. Each case retains machine-readable rejection reasons even when marker detection or calibration fails before packet decoding. The report contains only transfer size and decoder summaries; it does not contain packet bodies, file names/hashes, file contents, or raw frames. `decoderCpuSeconds` is intentionally diagnostic rather than a deterministic acceptance metric.

## High-speed candidate fixture

`simulator/high-speed-benchmark.mjs` runs the glyph4/glyph6 profiles through the same renderer, impairment model, glyph decoder, RS inner codec, fountain decoder, and SHA-256 verifier used by the application. The default glyph6 fixture is a 100,000-byte deterministic file, 30 nominal frames/s, 8% frame loss, and 5% duplicates. On 2026-07-31 it reconstructed exactly in 0.7333 simulated seconds at 136,363.64 bytes/s, with 21 received frames, 14/14 fountain rank, and about 1.3 seconds of Node decoder CPU. At the same loss pattern and 60 nominal frames/s, the identical verified fixture completes in 0.3667 simulated seconds at 272,727.27 bytes/s. These are clean geometry-neutral high-speed candidate results, not hardware claims; the 60 fps result is the favourable stationary mode that now exceeds the Decimen comparison floor.

Stress cases are intentionally separate from the headline baseline. The 1728-pixel glyph6 path rejects many small-rotation/blur cases because four-by-four glyph subcells are only about three camera pixels wide. The wider 112 × 63 glyph4 layout uses roughly 3.9-pixel glyph subcells and completed the mild rotation/perspective/exposure/noise fixture with zero rejected frames and exact reconstruction in a 100 KB run. Stronger blur and rolling-shutter cases still fail and remain hardening gates. Soft glyph erasures are now passed into RS, and the next gate is measured against recorded camera fixtures.
